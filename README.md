# GridFlex Neighbourhood

**Making clean power dependable, neighbourhood by neighbourhood.**

GridFlex is a software-only prototype for coordinating local renewable generation, flexible demand and shared battery storage in an Indian neighbourhood. It compares an uncoordinated baseline with a forecast-led GridFlex dispatch over a synthetic 24-hour day. All displayed results are generated by the simulation and all financial values are prototype assumptions.

## Solution and demo

The Neighbourhood Energy Coordinator uses a transparent daily demand profile and solar/wind profiles, detects a shortfall, shifts a share of flexible demand, dispatches a community battery within SOC and power limits, and uses grid supply for remaining net load. The default demo represents 500 households, 250 kW solar, 50 kW wind and a 500 kWh shared battery.

Suggested 2–3 minute demo: start on Overview, inspect the forecast and current supply, open Simulation, choose **Grid outage + renewable shortfall**, run comparison, then show the paired availability, unserved energy, critical service and cost. Open Resident view to see a plain-language flexibility tip, then Architecture to explain the data and decision path.

## Run

Requires Node.js 20 or later. In two terminals:

```sh
cd backend
npm install
npm run dev
```

```sh
cd frontend
npm install
npm run dev
```

Open the Vite URL (normally http://localhost:5173). Vite proxies `/api` to port 3001. Backend defaults to port 3001 and can be changed with `PORT`. No database, secret, or external service is needed. `.env.example` documents the optional backend port.

## Technology and API

React, Vite, JavaScript, Recharts, Lucide, Node.js and Express. In-memory demo state is used; the latest run replaces it until the server restarts.

## Model and assumptions

The 24-hour simulation has 96 steps at 15 minutes. Demand uses overnight, morning and evening profile peaks with deterministic variation. Solar follows a daylight curve, modulated by scenario and a small deterministic fluctuation; wind varies over time. The current forecast is a transparent profile-based estimate with ±14% illustrative bounds, not a trained model. Configurable inputs are validated by UI ranges; raw API inputs are intended for demo use.

Battery defaults: 500 kWh, 30 kW max charge/discharge, 20–95% SOC and 90% round-trip efficiency (applied as 90% on discharge and charge in this simplified accounting). The GridFlex dispatcher shifts participating flexible demand during net-load gaps, discharges before grid support, and charges from surplus renewable generation. Critical service and grid availability are tracked. This is an educational comparison, not a validated power-flow or market dispatch model.

## Reliability formulas

- Supply availability = served energy / (served energy + unserved energy) × 100.
- Unserved energy = required energy minus served energy, integrated over each 0.25-hour step.
- Outage duration = sum of 0.25-hour intervals with unmet demand.
- Critical load availability = critical energy served / critical energy required × 100.
- Renewable utilization = renewable energy used / renewable energy generated × 100.
- Improvement = GridFlex supply availability minus baseline availability, in percentage points.

## Economics

All financial values are explicitly estimates from prototype assumptions. Default energy tariff is ₹8/kWh, peak tariff ₹12/kWh; simple daily energy cost is grid import times tariff plus evening peak adder. Avoided cost compares that estimated GridFlex import bill with the baseline import bill. Battery capital cost, lifecycle degradation and financing are not included in payback; the prototype does not claim guaranteed savings.

## Indian distribution-grid relevance

The configurable profile includes residential morning/evening demand, shared infrastructure, water pumping, cooling, EV charging and a health centre. It is intended to help discuss variable renewable output, evening peaks, local congestion, reliability and affordability. It makes no claim about a particular DISCOM or feeder.

## Limitations and future scope

Synthetic deterministic data; aggregate neighbourhood balance; simplified priority, battery, tariff and outage rules; no reactive power, voltage, network topology, battery degradation, stochastic weather or user-level consent model. Forecast bands are illustrative. Future versions could add smart-meter/weather inputs, validated ML forecasts, feeder constraints, rooftop solar, EVs, real battery controllers and utility integrations. None is required to run this prototype.
